# Bouncer Architecture Skill

Reference for Nefarious's bouncer subsystem: persistent account-anchored sessions, the alias multi-connection model, connection-class gating, and the hard invariants that keep cross-server state consistent. Read this before writing or modifying bouncer code.

> Direction (2026-05-17): **sessions are configuration profiles, not identities.** One bouncer identity per account; per-profile channel lists reconcile to a network-membership union. Multi-session-as-multi-identity is OFF the roadmap. The `(account, sessid)` keying shape still works but now means `(account, profile)`.

## Session System

- `bounce_revive()` transplants a new client's socket onto a HOLDING ghost. Must transfer **ALL** connection metadata (IP, listener, confs, sockhost, port) or the ghost retains stale data.
- `bounce_create_ghost()` creates MDBX-restored ghosts via `make_client(NULL, ...)`, which allocates a Connection → `MyConnect(ghost) = TRUE`. Hold-awareness in /CHECK comes from session-state inspection (`bounce_get_session()` / hold_str), and WHO shows held ghosts with a `G` away-flag (the lone `IsBouncerHold` display guard, in `whocmds.c`) — there are no `IsBouncerHold()` guards in CHECK or WHOIS.
- `BounceSessionRecord` persists connection metadata (IP, sockhost, listener port); the on-disk record is at `BOUNCER_DB_VERSION 12` (`include/bouncer_session.h`; v11 appended the snomask fields, v12 the compact Keycloak id `bsr_kc_id`). The frozen v7–v11 layouts (`BounceSessionRecord_v7` … `_v11`) stay for migration reads; a migrated record is re-persisted. Reconciled on revive.
- `cli_session_id` must be synced from `hs_sessid` on every session-establishing path (`bounce_attach`, `bounce_setup_local_alias`, AND `bounce_revive`). Revived ghosts otherwise carry freshly-minted sessids from `bounce_create_ghost`, breaking any code that keys on agreement.
- **Hold duration (2026-10-20, spec: testnet `.claude/para/resources/bouncer-adaptive-hold-spec.md`).** A hold is the EARNED hold, not `BOUNCER_SESSION_HOLD`: base + base/4 per connection (`hs_connect_count`) + 1 h per 24 h attached (`hs_total_active`, accrued at hold from `hs_attach_time`, which create/attach/revive set), capped at `BOUNCER_MAX_HOLD`, then decayed while idle (after `BOUNCER_HOLD_DECAY_PERCENT` of it, the rest halves per quarter, never below base). `bounce_hold_remaining()` is the ONE source for the timer, `BOUNCER LIST/INFO` and `/CHECK`; the timer re-arms at the grace point and each decay unit (`bounce_arm_hold_timer`), so `t_expire(&hs_hold_timer)` is the next re-evaluation, not the expiry. Replicas learn the connect count by `BX U <primary> cc=<n>` (burst, attach, revive) and the active time by `BX U <primary> ta=<seconds>` (`bounce_emit_total_active`: hold, promote, burst, adopt; receivers keep the larger figure), so a server that becomes the holder arms the hold from the session's real history. Never arm `hs_hold_timer` directly with a feature value again.
- **Shadow system fully removed** (2026-03-07): all shadow functions, structs (`ShadowConnection`), globals (`current_shadow`, `suppress_shadow_dup`, `mirror_to_shadows`) and the BS S/W/N/R/O/XS relay deleted (~3000+ lines across 20+ files). Aliases are the only multi-connection mechanism.

## Alias System

- Each alias connection gets its **own Client struct** with its own P10 numeric, CAP state, and `CHFL_ALIAS` channel memberships. Normal IRC routing works without special duplication.
- Aliases are introduced via **BX C, not the N token** — other servers must never receive a Q token for an alias. `exit_client()` sends **BX X** instead.
- `m_quit()` and the `s_bsd.c` disconnect handler have early returns for aliases — they skip hold logic.
- `bounce_promote_alias()` promotes alias→primary on disconnect — the most recently ACTIVE alias wins (local: idle clock; remote: `ba_last_active`, kept live by `BX U <numeric> la=<ts>` on each connection's first message after 5 min quiet, since 2026-09-03), oldest connection as the tiebreak — and sets `hs_state = BOUNCE_ACTIVE` after promoting. `bounce_session_last_active()` gives the session-wide last activity (WHOIS idle uses it). `m_quit` immediate-promotes local aliases; cross-server (remote-alias-only) still defers.
- **Session move** (cross-server): `bounce_alias_create()` calls `bounce_promote_alias()` then exits the ghost with `FLAG_BOUNCER_INTERNAL_DESTROY` (`SetBouncerInternalDestroy`), gated on promote success — NOT `FLAG_KILLED`, which would trigger whole-session teardown (the opposite of a seamless move). The BX P handler on remote replicas must ALSO set `hs_state = BOUNCE_ACTIVE`.
- `CapRecipientHas(cli, cap)` is simplified to just `CapOwnHas(cli, cap)` — each alias owns its caps. `CapRouteContext` (renamed from `ShadowTagContext`) handles per-connection cap routing in channel send functions.

- **Per-connection away replicates as `BX U <numeric> aw=<0|1|2>`** (2026-09-11): a connection's OWN state (2 = `AWAY *`, draft/pre-away), emitted by its server on change and in the link burst; receivers keep `ba_away`/`hs_primary_away` (+`_known`). The webpush attention rule and the away aggregation read it for remote members instead of the session's mirrored aggregate, which a present sibling hides. Activity (`la=`) is emitted once per quiet period = min(300 s, half the account's webpush idle window) (`bounce_activity_quiet`), so a replica's reading is always fresher than the window it is judged against.

## Connection Classes

- `CRFLAG_BOUNCER` forces bouncer auto-create/resume per-class.
- `CRFLAG_REQUIRE_SASL` gates connections until SASL is available. The check in `attach_iline()` (s_conf.c) must consider ALL SASL sources: `sasl_local_available()`, `auth_iauth_handles_sasl()`, `get_sasl_mechanisms()`, and the legacy fallback.
- For legacy services (X3 without dynamic mechanism broadcast), `require_sasl` falls back to `FEAT_SASL_DEFAULT_MECHANISMS` + a server-connectivity check.
- `include/class.h` holds the `ClassRestrictFlags` enum.

## Hard Invariants & Audit Rules

These are the rules whose violation has repeatedly caused crashes or session loss. Treat each as a checklist item when touching the relevant path.

1. **`hs_state = BOUNCE_ACTIVE` must be set in BOTH `bounce_promote_alias()` AND the BX P S2S handler** — promote runs locally, BX P runs on replicas. Missing either destroys the session on disconnect.
2. **Every `cli_name(alias)=` rename for a `MyConnect(alias)` must be paired with `sendcmdto_one(alias, CMD_NICK, …)`** — otherwise the alias's own socket never sees the NICK echo (covered by testnet `tests/src/ircv3/bouncer-nick-lockstep.test.ts`).
3. **Any `%s%s` P10-numeric construction in a BS-token handler must use `cli_yxx(sptr)` (live sender), never `session->hs_origin`** (recorded at create-time, stale after cross-server rebind). Using hs_origin caused live-session hijack onto a leftover ghost during burst convergence.
4. **Any new emit between the 005 block and `motd_signon` in `register_user()` must be mirrored on both bouncer fast paths** (`bounce_revive` + `bounce_setup_local_alias`), which hand-roll the welcome block and skip register_user's tail.
5. **Every S2S `CMD_NICK` introduction must call `bounce_set_n_sessid_hint()` before emit** (audited 2026-05-02; four sites clean).
6. **Don't add a flag to spare an alias from the session-destroy cascade** — `FLAG_KILLED` on any alias triggers whole-session teardown (`exit_one_client`, s_misc.c ~348-371: the KILL is propagated to a local primary) by design; cross-boundary legacy collision means whole-session loss. Fix outcomes, not consequences. (There is no `FLAG_KILL_NICK_COLLISION` — don't introduce one to gate this.)
7. **The reconcile yield must broadcast Q, not suppress via `FLAG_KILLED`** — enforced in the BS C reconcile handler (`bounce_handle_bsc`): the losing ghost is exited via `exit_client(..., "Bouncer session moved")` so the normal Q cleans up the peer's phantom; suppressing it leaves a stale ghost. (The old BX R token that carried this is retired in Phase 5.)
8. **`set_nick_name` MyUser(sptr) block must use `sptr`, not `cptr`** — alias-source rewrite breaks the historical cptr==sptr invariant and deref's `cli_user(server)==NULL` on cross-server alias rename (SIGSEGV).
9. **UserStats opers/inv_clients must balance across the alias lifecycle.** The counts are flag-keyed: `FLAG_COUNTED_OPER` / `FLAG_COUNTED_INV` (`include/client.h`) record whether a client currently contributes +1. `userstats_count_sync()` (s_user.c) reconciles after every umode change (`set_user_mode`, `m_oper`, `bounce_copy_umodes`, alias promote, the oper grant/clear paths) and `userstats_count_clear()` releases at exit (the `exit_one_client` alias, hold and normal branches, plus `free_client` in list.c as the backstop for bouncer paths that free via `remove_client_from_list` without `exit_one_client`, e.g. the BX X reap). No MyConnect gate is needed: the flag says whether the client was counted, so a never-counted remote alias is a no-op. Never ++/-- the counters by hand — an unpaired decrement (the old exit-only fix) underflows and asserts; an unpaired increment trips the `opers <= clients + unknowns` assert.
10. **Every S2S egress sourced from a client must rewrite alias→primary for legacy / not-BX-aware peers.** Aliases are introduced via BX C, which legacy peers silently drop, so an alias numeric on the wire toward a legacy peer is an unknown source — the message gets silently dropped on receive (no `ERR_SERVICESDOWN`, no `421`). Audit checklist: any new `sendcmdto_one(sptr, CMD_PRIVATE|CMD_NOTICE, ...)` toward a non-`MyConnect` target needs `from = (IsBouncerAlias(sptr) && cli_user(sptr)->alias_primary) ? cli_user(sptr)->alias_primary : sptr` with the appropriate direction guard (`cli_from(from) == acptr` when acptr is the destination server; `cli_from(from) == cli_from(acptr)` when acptr is a remote user). The pre-existing omission in `relay_directed_message` / `relay_directed_notice` (`ircd_relay.c`) caused `X3 ping`-style Pseudo commands to silently fail for users currently in alias status — fixed by mirroring `relay_private_message`'s rewrite block at all four directed-relay send sites. **Hunt-routed commands** (`hunt_server_cmd` / `hunt_server_prio_cmd`, s_user.c — WHOIS/STATS/LINKS/MOTD/etc.) were the next miss (2026-09-02): an alias's routed `WHOIS nick nick` died silently at the first legacy hop. Both now rewrite alias→primary except toward the primary's own direction. **Companion rule:** `send_buffer` delivers only to the addressed connection, so a reply addressed to the rewritten primary would land on the *other* device — `do_numeric` therefore mirrors S2S-arriving plain numerics for a local primary to its local aliases (never label-batched ones). Any new alias→primary egress rewrite needs a reply-delivery story for the asking connection.

11. **Session echoes (a PM sent from another device) go only to connections that negotiated `echo-message`.** The echo is sourced from the user's own nick; a client without echo-message files it under its source, i.e. a query with the user's own nick (field report 2026-09-15). Gated at `bounce_echo_pm_to_session`, the multiline DM loop in m_batch.c, and on receipt of BX E / BX M; replicated as `BX_CAP_ECHO_MESSAGE` in `BX U caps=`. Test: testnet `tests/src/ircv3/bouncer-session-echo-cap.test.ts`.

12. **Account deauth is account-level, and the aliases are told BEFORE the sessions go.** `bounce_account_deauth_apply()` (one body for the AC U receiver and the Keycloak webhook) emits `BX U account=` for every session of the account first -- `bounce_emit_alias_update` finds the aliases through the session roster, so an emit after the destroy loop is a silent no-op (that was B-1's second half, live on both callers until 2026-09-23). A local alias gets the clear only through that emit's local-apply pass; the S2S broadcast skips the primary's own server. A held ghost has nothing to revive into once the account is gone: its session's aliases are exited the way a KILL of the ghost would, and the body returns non-zero so the caller exits the ghost itself after the relay/AC U (`ClearBouncerHold` + `exit_client`); a ghost left with no session and no timer holds the nick forever. Sockets are only ever exited locally (B-2: `exit_client()` on a remote victim splits the network); the account is cleared everywhere -- a remote client's replica here plus AC U to its home server. KILL_ON_DELETE runs a kill pass first: a primary that anchors a session goes through `bounce_kill_session` (every alias, everywhere, then the record) before it is deauthed and exited, otherwise a plain socket exit holds the session or promotes an alias and the deleted account lives on. Classifier: `bounce_deauth_classify()` (`ircd/bouncer_deauth.c`, pure, cmocka). Tests: testnet `tests/src/ircv3/bouncer-deauth-local-alias.test.ts`, `tests/src/ircv3/bouncer-deauth-cross-server.test.ts`.

13. **A server notice mask (snomask, +s) is known only where its connection is** (2026-10-21, plan: testnet `.claude/para/projects/bouncer-snomask-cross-server-2026-10.md`). A remote Client's `cli_snomask` is `con_snomask(cli_connect(cptr))` and `make_client(from)` shares the uplink link's Connection, so it is the LINK's field, shared by every client behind it: never read it as a user's mask, and never `set_snomask()` a remote Client (it links the client into opsarray, reroutes notices onto the server link, and leaves a dangling node at exit since only MyUser clients are unlinked). +s is local-only (P10 never carries it), so `bounce_copy_umodes` copies `FLAG_SERVNOTICE` only from a local source. `bounce_member_snomask()` is the one reader: live local mask, or `hs_snomask` for a held ghost (close_connection zeroed its own; `bounce_hold_client` saves it, the revive restores it, it is persisted in DB v11 and used by the oper grant). The other servers learn it by **`BX K <member YYXXX> <mask> <lamport-ts>`**, routed toward the member (any member, primary or alias), sent by `bounce_sync_session_snomask()` on a change and by the BX C receiver for a local primary; receivers keep the later stamp (lower server numeric on a tie), set +s iff the mask is non-zero, tell the client (MODE ±s, 008), and never re-sync onward. In `set_user_mode`, `snoc` is the local connection the mask belongs to (the target if ours, else the asking alias of a remote primary). Test: testnet `tests/src/ircv3/bouncer-snomask.test.ts`.

14. **A session's mode sync tells every member, and copies only what is the session's.** `bounce_sync_session_umodes(source, source_before, told)` snapshots the other live local members, copies the source's modes and privileges onto them, then sends each its own `MODE` diff (and 008 when its mask changed) -- except `told`, the connection `set_user_mode` already echoed to. A device attached when another device opers (or X3 opers the session) is told it is an oper. Not copied: `FLAG_SSL` (+z, each connection's TLS is its own). A `-o` strips privileges and the oper handler from every member (`bounce_strip_oper_privs`), never only the flags: a member left with privileges after `-o` runs oper commands and the ones that assert `IsAnOper` (KILL, CLOSE, CONNECT) abort the server. Tests: testnet `tests/src/ircv3/bouncer-oper-sync.test.ts`, `bouncer-umode-announce.test.ts`.

15. **A dead socket is a disconnect, not a quit.** `dead_link()` records its reason in `cli_exit_reason` (Connection, `EXITREASONLEN`), never in `cli_info` (that was the realname clobber: a held session kept "Max sendQ exceeded" as its realname, persisted and replayed it). Every path that exits a dead client (`exit_dead_client`, s_bsd.c: the read/write callbacks, the parse loop, `check_pings`) asks the bouncer first, so a session primary holds like a dropped connection; an alias exits (promotes). `bounce_revive` clears the reason, and repairs a realname an older build clobbered (`exit_reason_is_clobbered_info`). Test: testnet `tests/src/ircv3/bouncer-dead-link-hold.test.ts`.

16. **A session is bound to one Keycloak account, both ways** (user, 2026-10-23: "a new id should not attach to an old session, just like an old session should not get tied to a new id").  The session carries its own id, `hs_kc_id` (set at create from the creating login; adopted only while empty -- the transition: X3 logins, records from before the id was kept -- through `bounce_session_adopt_kc_id()` at attach, revive and a same-name SASL re-login; persisted as `bsr_kc_id`; replicated by the fork-only `BX U <primary> kcid=<id>` after BS C, after BS A and in the burst; a replica never takes a different one).  Read it with `bounce_session_kc_id()` (hs_kc_id, else a member under the session's account).  No login joins a session of another id by any path: `register_user`'s revive check refuses the revive; `bounce_auto_resume()` gates every attach before its branches, after resolving a remote session's primary (`bounce_kc_join()`, pure, cmocka: join / end the previous user's leftover held here with nothing connected -- only for a login Keycloak itself confirmed, `cli_saslkcidlive` (a grant, a user lookup, introspection; never a cached answer or a locally checked token a deleted user still holds; when a conflicting session exists, the cache is skipped and a locally valid token is introspected, so the login becomes live; user 2026-10-23) / refuse -> `BOUNCE_RESUME_REJECT_KC_CONFLICT`, an exit like REJECT_DUPLICATE); `BOUNCER ATTACH` refuses; the S2S rebind vetoes (`bounce_rebind_kc_conflict`).  No session is tied to a new id: a connection that proves its own account name under another id fails SASL (904, `sasl_complete_login` step 0) and keeps what it had; and sessions of different ids are never merged after a split (user, 2026-10-23): the same-nick D.2 merge falls back to classic collision, the post-burst reconcile skips the candidate, BS C's cross-sessid convergence and same-token yield neither retire, rename nor mirror, `bounce_hs_client_assign_checked()` never installs a primary of another id, and the BX C account fallback never files an alias into a session of another id.  The D.2 skip falls into classic collision: older nick wins, the younger loses its whole session (accepted, user 2026-10-23).  Every fork server must run this together: an older fork peer has no gate and merges without the id check.  A missing id never vetoes.  No webhooks on prod: nothing ends the old owner's sessions at a Keycloak delete.

17. **A remote alias's memberships mirror its primary's, on every server** (the mirror invariant; rulings W3-T12c-3-e/-f, 2026-10-30).  Another server's device is a member here, as an alias, of every channel its primary is in here -- with the primary's op/halfop/voice and op level and its JOIN msgid and time -- minus a +Z channel for a plaintext device (FLAG_SSL, carried in the BX C modes) and minus every local (`&`) channel, which exists on one server alone.  Filed at the BX C create, re-file and convert and at the burst (`bxc_mirror_primary_channels()`), and at each later JOIN of the primary (`bounce_sync_alias_join()`); a BX C's channel list is cut at the line's length, so it is never the source, and a membership is kept only where the primary is in the channel here.  A device of another server's primary that JOINs our `&` channel gets 403 (m_join's alias rewrite would make the remote primary a member of a channel its server does not have).  No user count moves (#9) and nothing goes on the wire (#10).  Open, second W3 push: the device's OWN server does not yet mirror a demoted or swapped face's new channels (register).

18. **A line under the survivor's server's name goes only away from that server** (ruling W3-T12c-2a-f2a).  The D.2 swap's `KICK :Net Rider` for a channel the survivor may not keep (+Z/+O/+a) is sourced as the survivor's own server -- `m_burst`'s Net Rider form, sourced as the kicked member's server; the member the legacy links hold is the survivor, under the face they renumbered -- so receivers remove the member at once and stock raises no HACK(4).  Such a line is sent only to links that know the survivor through our BX P, never toward the survivor's server (P10's direction check then passes on every receiver).  Any new line sent under another server's prefix needs the same two rules.

19. **One session, one id, after every merge.**  Whatever makes two copies one session -- a held ghost's yield (`bounce_yield_held_ghost`), a same-nick swap (D.2, `bounce_swap_take_id`), BS C's follow (`BOUNCE_BSC_FOLLOWED`) -- leaves one id on both servers: outside a burst the merging record takes the incoming session's id at once (`bounce_yield_id()` TAKE_ID, `bounce_session_take_id()`: the record, its unmirrored mark, every connection it names); inside a burst the burst's BS C decides (`bounce_follow_keeps_id()`).  Two ids on one session drop a member's carried end (BS E for an id the holder has no record of) and leave the other server's devices out of the holder's end (W3 final fix wave, I-1).

## Burst & Convergence

- The `server_estab` burst gate is dynamic: skipped when `bounce_convergence_pending()` returns 0, with event-driven release at attach/revive/EB. The 30s timer is now a stall-fallback only.
- The N-burst tail is gated dynamically by `bounce_convergence_pending()` and released event-driven by `bounce_release_idle_gates()` at convergence-completion sites (plus a 1s fallback tick). The old `BX F`/`BX R`/`BX J` handshake tokens are **retired (Phase 5) — silently dropped** by the BX handler; `FLAG_BXF_AWARE` is still announced on link but its token handler is now a no-op. Held ghosts remain visible to legacy peers; phantom cleanup is via a normal Q.
- `bounce_post_burst_reconcile` (in `ms_end_of_burst`) merges multi-primary-same-session states that survive cross-sessid convergence and that the D.2 at-N-time check misses (no nick collision). Legacy_face suppression in s_serv.c is session-keyed so non-bouncer same-account clients aren't hidden from legacy peers.
- `bounce_peer_has_inbound_data()` (a link mid-burst, or with unread bytes -- TLS `SSL_pending()` included) guards `bounce_auto_resume`'s "no session, create new" path; `BOUNCE_RESUME_DEFER_PEER_INBOUND` defers (the steady-state BS C race).  How a deferred login waits and drains: "The deferred-login machinery" below.
- BS C's convergence keeps the strcmp-LOWER base64 session id (not always the older UUID v7); both ends compute it alike, and the hold clock follows by `cc=`/`ta=` (larger wins).  Never change the comparison: a mixed pair would split.

## Second fork server (W3, 2026-10)

Prod shape: F2 links directly to F1 (Fractal); F1 also links to the stock legacy hub L, with X3 behind L.  Plan: testnet `.claude/para/projects/2026-10-24-s2s-w3-bouncer-cross-server.md`; register: testnet `.claude/para/areas/deferred-items.md`.

**Deploy rule (user, 2026-10-30).** No F1-F2 link until BOTH run the W3 head; `P10_MESSAGE_TAGS` TRUE in both configs before the link comes up.  Flag H is announced only in the SERVER line, so after any runtime change of the feature: SQUIT and relink.  F2 may be built and started early if it stays unlinked.  A mixed pair brings back the session-loss paths W3 closes (the final review's HARM list A1-A7, B1, B2, in the register: no worse than two pre-W3 servers, worse than prod without F2).  With tags off the session-id-only rebind (`4673fa96`) never authorizes, and every same-session relink is a classic-collision KILL.

**Flag H and the `,H` mark.** A server announces SERVER flag `H` (`FLAG_HOLDMARK`) only while `P10_MESSAGE_TAGS` is on, at link time (`FLAG_HOLDMARK_SENT`: our SERVER line to that link announced it).  Its users' N then carry `,H<h|p|n>` after `,S` (held ghost / live session primary / live in no session), stamped only by the home server and copied by relays; a mark is trusted only when every hop from its home announced H and we announced H on the link (`bounce_hold_marks_trusted`).  H now also means "reads BS E, with the letters D/O/T/R" (`bounce_route_reads_carry`: every server from the primary's to us announced H) and gates the non-burst re-announces (`IsHoldMark`).  A future change to BS E (a new letter, a new field) needs a capability of its own: H cannot carry it.

**Only the holder ends a session; a member's end is carried there (BS E).** The holder is the server the primary is on (live, or a held ghost).  Another server's BS X ends that server's copy and nothing of the holder's.  A member or an oper elsewhere that ends the session sends `BS E <account> <sessid> <D|O|T|R> :<reason>` toward the primary (`bounce_member_end`, route CARRY):
- **D** BOUNCER DISCONNECT; **O** hold off (BOUNCER SET HOLD off, PERSISTENCE SET OFF, MODE -b: the hold preference goes to 0); **T** PERSISTENCE DETACH (O, and the account's webpush subscriptions are forgotten; refused by the holder's own `hs_enforced`, as its local command would be); **R** BOUNCER RESET, ORESET, a ban (every connection ends, the primary too).  D, O and T leave a live primary carrying on outside the session.
- The asker applies no side effects; the holder applies them once it accepts the end (`bounce_end_apply_side_effects`), then ends it (`bounce_end_here`).
- The receiver's `bounce_bse_action`: END (the primary is ours, or nobody's), FORWARD (further on, every hop reads BS E), DROP (no record, an unknown letter, the primary back toward the sender, a hop that would drop it), RETURN.
- **The RETURN bound (W3 12c-4).** A server returns the line once, sourced from `&me` (a prefix not from the arriving link is dropped as a fake direction), back to the device's server, only when its own promote handed the session to that device behind the sender (`hs_handoff` = the device's YYXXX, set only with that promote's BX P, which is queued ahead on that link), the record is ACTIVE and the link is not burst-gated.  No hop count: every supersession clears `hs_handoff` (another server's BX P through the checked install, its BS D, HOLD_OLD, every local install), so a second return needs a real promote back across the link in between.  The return does NOT clear `hs_handoff`: the crossed path reads it.
- **The note (END_NOTED).** The returned end is noted on the record (`hs_end_noted` / `_how` / `_reason`; a reset-kind R overrides any other kind, else the first noted wins; cleared with every `hs_handoff` write and at destroy).  If the device's own BX X then crosses the promote, `bounce_crossed_bxx_action` answers END_NOTED: the session ends by the noted end -- its kind, reason and side effects (a noted T refused under our `hs_enforced` falls back) -- and the remote primary is never exited (B-2).

**Crossed promotes.** On the device's server a BX P naming a new face that already left here (its exit crossed the promote) keeps the old primary in the slot until the holder decides (HOLD_OLD: `hs_crossed_face` = the face our legacy links now hold, `hs_crossed_kept` = the kept primary; the backstop ends the record after `ORPHAN_WAIT_MAX`).  A later BX P from the noted face moves the kept primary to the device that takes over (FOLLOW_CROSSED); a BX P whose new face left too renumbers the note (RENUMBER_CROSSED).  FOLLOW-STALE (the note's kept primary is no longer in the slot): the face is retracted toward the legacy links (a raw QUIT from it), then the line is forwarded.  While a record keeps its primary this way the chooser answers WAIT: a login never becomes an alias of a primary its own server let go (final fix wave, M-2).

**Same-nick meetings at N time (D.2).** `bounce_nick_verdict()` (pure, both servers compute it from the same facts) and `bounce_nick_action()`: REFUSE / RETIRE / REBIND (drop) / SWAP / YIELD / CLASSIC.  The swap and the yield keep one id (#19).  A retire exits only a held ghost of ours (`retire_ghost_ours()`: never another server's client in the slot, B-2).  D-LH, a live login in no session meeting a held ghost, was decided 2026-10-27 (user): (b), the classic rules (`BOUNCE_LIVE_LOGIN_WINS` 0).  Two fresh sessions of one account made within one link round trip on F1 and F2 stay apart (BS C outside a burst while the receiver's own is live: `bounce_bsc_fresh_apart`, the unmirrored mark) until the next link burst, until one ends (BS X: `bounce_bsx_reannounces`), or until their nicks meet (accepted, user 2026-10-27).

**What L and X3 see from a fork server.** Design intent #7 said BX P and Q only.  Now:
- BX P renumbers a face in place (rebind, swap, yield, promote, the crossed re-promote); Q retracts a face (a raw `<YYXXX> Q` for a crossed face); plain N.
- The D.2 swap's `KICK :Net Rider` (#18), and, when F2 is the loser, F1's relays of the swap's J, memberless or zannel BURST and server MODE.  The two HACK(3) notices they raise (the J's empty-channel wipe on the survivor's fork server, the server MODE) are accepted (user, 2026-10-28).
- Never a tag.  A legacy server needs upstream >= `c066405` (the BX handler), or it keeps the old numeric and KILLs the user at the next NICK.
- A BX P whose numerics are not five characters is dropped, never forwarded (`bounce_bxp_forwardable()`: a stock server reads a short one as a one-character server plus a client and can renumber an unrelated user; final fix wave).
- Stock L relays any BX P onward (X3 included): harmless while the fork servers stay contiguous (no fork island behind L).
- An X3 `SVSQUIT` of a session member ends the whole session, as a KILL does (`bounce_forced_exit`).

**The +b join and the shared chooser (user decisions U1-U3, 2026-10-28).** All three hold-on paths -- MODE +b, BOUNCER SET HOLD on, PERSISTENCE SET ON -- JOIN the account's existing session rather than make a second one (U3).  A refused join answers FAIL and +b is not set; nothing goes on the wire (U2).  The joiner's old face quits once everywhere ("Attached to <P>'s session", one msgid), its socket gets a PART for each of its own channels, and it ends up in exactly the session's channels (U1).  The planner is pure (`bounce_hold_on_plan`: NOOP / JOIN / JOIN_PROMOTE / CREATE / REFUSE_KC / REFUSE_FULL / REFUSE_TLS / REFUSE_UNREACHABLE / DEFER, a passing refusal); the umode path runs it at the tail of `set_user_mode` (`bounce_hold_on` -> `bounce_live_join`), never mid-loop.  An Operator block's umode never applies b (final fix wave).  Registration and hold-on read one chooser, `bounce_choose()` (rows from `bounce_choose_read()`): the Keycloak gate (#16) over every session, the best held session, then the first live one; WAIT for a record a peer has just announced (no BS A yet: `BOUNCE_ANNOUNCED_WAIT`) or that keeps its primary for a crossed promote; FOREIGN for a primary of another identity.  CMocka checks that registration and hold-on agree over every two-session state.

**The deferred-login machinery (W3 12c-2b).**
- A registration `bounce_auto_resume` defers (`BOUNCE_RESUME_DEFER_PEER_INBOUND`: a link mid-burst or with unread bytes, or the chooser's WAIT) goes back to the unregistered connection it was (`register_user_unwind()`: counted unknown, the unregistered command table, no numeric, nothing on the wire) and is queued.
- It drains at the end of a read: `bounce_link_input_read()` after any server link's read, once no link holds the queue back; and by its wait timer.
- A WAIT entry stays queued while its record is still unnamed (or still keeps a crossed primary), until its own wait end (`session_wait_until()`); the line that names the primary (BS A; the holder's BX P or BS X) drains it.
- A peer's N that took its nick while it waited is resolved at the drain (`pending_nick_resolve()`, as `check_auth_finished()` resolves a deferred nick); a nick still held elsewhere answers 433 and the client waits for a new NICK.
- A drained registration runs `register_user()` from the top, once.

**Skew classes, corrected (final review, lens 1 section 4; the commits are not rewritten).** D4: SKEW-SAFE (sender-local or receiver-local), RECEIVER-FIRST (the receiver lands in an earlier commit than any sender), CAPABILITY-GATED (a SERVER flag letter).
